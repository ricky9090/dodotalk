## 1. 项目概览

DodoTalk 的前身（当时名为 JSqueak-2021）是一个用纯 Java 实现的 **Squeak Smalltalk 虚拟机**（VM），最初由 Daniel H. H. Ingalls 在 Sun Microsystems 开发。该仓库是对 Victor Rodriguez 维护的 victorr/jsqueak 仓库的 fork，并在 2021 年进行了大量改进。项目现名 DodoTalk，本文保留当时的历史名称与上下文。

**核心目标**：用 Java 重新实现 Squeak 2.2 的完整 VM，使其能够加载并运行 Squeak 2.2 的完整映像文件（image file）。

### 1.1 当前功能状态

| 功能 | 状态 | 备注 |
|------|------|------|

| 显示输出 | 可用 | 支持 1/8/32 位色深 |

## 3. 核心数据结构

### 3.1 SqueakObject — 一切皆对象

```java
public class SqueakObject {
    short hash;        // 12-bit Squeak 哈希值
    short format;      // 4-bit 对象格式码（0-15）
    Object sqClass;    // 指向类对象（运行时从 Integer 解析为 SqueakObject）
    Object[] pointers; // 指针字段（固定字段 + 索引字段）
    Object bits;       // 索引二进制数据（byte[] 或 int[] 或 Double）
}
```

**Squeak 对象格式码（format）**：

| 格式 | 类型 | 说明 |
|------|------|------|
| 0 | 指针 | 无字段 |
| 1 | 指针 | 仅固定字段 |
| 2 | 指针 | 仅索引字段 |
| 3 | 指针 | 固定 + 索引字段 |
| 4 | 弱引用 | 固定 + 索引弱字段 |
| 6 | 字 | 索引字（无指针），如 Float |
| 8-11 | 字节 | 索引字节（无指针），如 String、ByteArray |
| 12-15 | 混合 | CompiledMethod：指针（literals）+ 字节码 |

### 3.2 SmallInt 的表示

SmallInt 不是 SqueakObject，而是直接使用 Java 的 `Integer` 装箱类型：
- 有效范围：`-0x40000000` ~ `0x3FFFFFFF`（31 位）
- 溢出哨兵值：`nonSmallInt = -0x50000000`
- `InterpreterHelper.isSTInteger(obj)` 检测：`obj instanceof Integer`

### 3.3 内存布局 — Squeak 对象头

Squeak 的对象头有 4 种类型（由低 2 位决定）：

| 头类型 | 值 | 结构 |
|--------|-----|------|
| SizeAndClass | 0 | 3 字头（header + class + format） |
| Class | 1 | 2 字头（class + format） |
| Free | 2 | 空闲块 |
| Short | 3 | 1 字头（含 compact class index） |

### 3.4 Context（上下文）布局

```
Context_sender = 0
Context_instructionPointer = 1
Context_stackPointer = 2
Context_method = 3
Context_receiver = 5
Context_tempFrameStart = 6
```

小帧大小：17 个字段；大帧大小：57 个字段。

## 4. 启动流程

```
1. Main.main()
   └─ Starter.BOOT_ARGS = new String[0]
   └─ Starter.boot()

2. Starter.boot()
   └─ BOOT_ARGS.length > 0 ? locateSavedImage() : locateBootableImage()
   └─ locateBootableImage()
      └─ SqueakConfig.getImagePath("squeak22.image.gz") → "/image/squeak22.image.gz"
      └─ class.getResource(imageFileResource) → 读取 resources/image/squeak22.image.gz
   └─ new SqueakImage(inputStream)

3. SqueakImage.loaded()
   └─ GZIPInputStream → DataInputStream
   └─ readImage(DataInput in)
      ├─ 校验版本号 6502（处理字节序）
      ├─ 读取头信息：headerSize, endOfMemory, oldBaseAddr, specialObjectsOopInt...
      ├─ 循环读取对象：解析头类型、format、hash、创建 SqueakObject
      ├─ oopMap: 旧 oop → 新 SqueakObject
      ├─ 构建 compact class 数组
      └─ objectMemory.installObjects() — 解析指针、字节、Float

4. new SqueakVM(image)
   ├─ image.bindVM(this)
   ├─ primHandler = new SqueakPrimitiveHandler(this)
   ├─ loadImageState()
   │   ├─ 加载 specialObjects 数组
   │   ├─ 获取 nilObj, falseObj, trueObj
   │   └─ 获取 specialSelectors
   ├─ initVMState()
   │   ├─ 初始化中断计数器、时钟
   │   ├─ 设置 interruptKeycode = 2094 (cmd-.)
   │   └─ initByteCodeTable() — 填充 256 个字节码执行器
   └─ loadInitialContext()
      └─ 从 Scheduler → ActiveProcess → suspendedContext 加载初始上下文

5. vm.run()
   └─ while(true) { b = methodBytes[++pc]; bytecodeTable[b].execute(b); }
```

## 5. 字节码解释器

### 5.1 字节码分派表

`SqueakVM.bytecodeTable[256]` 是一个 `BytecodeExcutor` 接口的数组，每个元素是一个 lambda 表达式。通过 `initByteCodeTable()` 初始化，将 0-255 映射到对应的执行器。

字节码范围分布：

| 范围 | 功能 | 执行器 |
|------|------|--------|
| 0-15 | push receiver variable | `pushReceiverVariableBytecode` |
| 16-31 | push temporary variable | `pushTemporaryVariableBytecode` |
| 32-63 | push literal constant | `pushLiteralConstantBytecode` |
| 64-95 | push literal variable | `pushLiteralVariableBytecode` |
| 96-103 | store and pop receiver variable | `storeAndPopReceiverVariableBytecode` |
| 104-111 | store and pop temporary variable | `storeAndPopTemporaryVariableBytecode` |
| 112 | push receiver | `pushReceiverBytecode` |
| 113-119 | push constants (true/false/nil/-1/0/1/2) | 对应执行器 |
| 120-125 | return | returnReceiver/True/False/Nil/Top |
| 128-130 | extended push/store | 扩展操作 |
| 131-134 | send | 单/双扩展发送 |
| 135-137 | stack ops | pop/duplicate/push active context |
| 144-151 | short unconditional jump | `shortUnconditionalJump` |
| 152-159 | short conditional jump | `shortConditionalJump` |
| 160-167 | long unconditional jump | `longUnconditionalJump` |
| 168-175 | long conditional jump | `longJumpIfTrue/False` |
| 176-191 | arithmetic shortcuts | 内联加减乘除、比较、位运算 |
| 192-207 | common selectors | at:/at:put:/size/next/equiv/class/blockCopy/value/new |
| 208-255 | send literal selector | 0/1/2 参数的消息发送 |

### 5.2 消息分派流程

```
send(selector, argCount, doSuper)
  ├─ getClass(receiver) → lookupClass
  ├─ findSelectorInClass(selector, argCount, lookupClass)
  │   ├─ 查 method cache（4路哈希探查）
  │   ├─ 遍历 class hierarchy 的 method dict
  │   └─ 找不到 → doesNotUnderstand:
  ├─ executeNewMethod(newRcvr, newMethod, argCount, primIndex)
  │   ├─ primIndex > 0 → tryPrimitive(primIndex, argCount)
  │   │   ├─ 成功 → 返回
  │   │   └─ 失败 → 回退到字节码执行
  │   └─ 分配 Context → 复制参数 → 跳转执行
  └─ checkForInterrupts()
```

## 7. 图形子系统 — BitBlt

### 7.1 BitBlt 工作流程

```
loadBitBlt(bbObject, argCount, doWarp, displayForm)
  ├─ 解析 sourceForm, destForm, halftoneForm
  ├─ 解析 destRect, clipRect
  ├─ 加载 ColorMap（支持新旧两种格式）
  └─ 设置 destIsDisplay 标志

copyBits()
  ├─ clipRange() — 裁剪到 clipRect
  ├─ destMaskAndPointerInit() — 初始化目标掩码和指针
  ├─ 选择复制循环：
  │   ├─ 无源：copyLoopNoSource()
```

## 8. 显示与输入

### 8.1 Screen 显示模块

基于 **Swing JFrame + JLabel** 构建：

- 使用 `Timer` 作为心跳（30 FPS），定期检查 `fScreenChanged` 标志并触发 `repaint()`
- 支持 1 位（黑白）、8 位（256 色）、32 位（ARGB）色深
- 8 位色使用从 SqueakJS 移植的 256 色调色板
- 位图缓冲区通过 `setBitsV2(int[], depth)` 更新

### 8.2 鼠标输入

`MouseStatus` 实现 `MouseInputAdapter`，将 Java 鼠标按钮映射到 Squeak 按钮：

| Java 按钮 | Squeak 值 | Squeak 含义 |
|-----------|-----------|-------------|
| 左键 | 4 (RED) | 选择 |
| 中键 | 1 (BLUE) | 窗口菜单 |
| 右键 | 2 (YELLOW) | 面板菜单 |
| Ctrl+左键 | 2 (YELLOW) | 等效右键 |
| Alt+左键 | 1 (BLUE) | 等效中键 |

### 8.3 键盘输入

`KeyboardQueue` 维护一个大小为 8 的字符队列，将 Java KeyEvent 转换为 Squeak 键码：

- 特殊键映射：Home→1, End→4, Enter→13, Left→28, Right→29, Up→30, Down→31
- 修饰键：Shift=8, Control=16, Command(Alt/Meta)=64

### 8.4 输入通知线程

`InputNotifyThread` 是一个独立线程，以约 33ms 间隔循环：
1. 设置 `screenEvent = true`，调用 `SqueakVM.class.notify()` 唤醒 VM
2. 等待 200μs
3. 设置 `screenEvent = false`
4. 等待 33ms

这解决了早期 JSqueak 中输入延迟的问题。

## 9. 对象内存管理

### 9.1 对象表（Object Table）

```java
ArrayList<WeakReference<Object>> objectTable;
```

- 初始容量：120,000
- 增长步长：10,000
- 使用 `WeakReference` 允许 Java GC 回收不再引用的 Squeak 对象
- 哈希生成：`lastHash = 13849 + (27181 * lastHash)`

### 9.2 垃圾回收

```
performGC()
  ├─ 循环 5 次 partialGC()
  │   ├─ System.gc() — 请求 Java GC
  │   └─ reclaimNullOTSlots() — 压缩对象表
  ├─ 第 3 次失败后 clearCaches()（方法缓存 + at 缓存）
  └─ 仍不够 → fullGC() + ensureCapacity
```

`reclaimNullOTSlots()` 遍历对象表，将 `WeakReference.get() == null` 的槽位移除，保留对象的创建顺序（对 Squeak 弱对象至关重要）。

## 10. 映像文件格式

### 10.1 文件结构

```
squeak22.image.gz  ← gzip 压缩
  └─ DataInputStream (big-endian / 自动字节序检测)
      ├─ version: 6502 (4 字节)
      ├─ headerSize (4 字节)
      ├─ endOfMemory (4 字节)
      ├─ oldBaseAddr (4 字节)
      ├─ specialObjectsOopInt (4 字节)
      ├─ lastHash (4 字节)
      ├─ savedWindowSize (4 字节)
      ├─ fullScreenFlag (4 字节)
      ├─ extraVMMemory (4 字节)
      ├─ [padding to headerSize]
      └─ 对象序列...
          ├─ 对象头（1/2/3 字，由类型位决定）
          ├─ class 指针 / compact class index
          ├─ format + hash
          └─ 数据（pointers / bits / 方法头+literals+bytecode）
```

### 10.2 对象安装流程

1. 读取原始 int[] 数据创建 `SqueakObject(classInt, format, hash, data)`
2. 注册到 `ObjectMemory.objectTable`
3. 构建 `oopMap`（旧 oop → 新对象）
4. 对每个对象调用 `install(oopMap, ccArray, floatClass)`：
   - 解析类指针（compact class index 或直接 oop）
   - 格式 0-4：`decodePointers()` 将旧 oop 转换为新对象指针
   - 格式 6 + Float 类：将两个 int 转换为 double（注意无符号右移！）
   - 格式 8-11：`decodeBytes()` 提取字节数组
   - 格式 12-15（CompiledMethod）：先解析 literals 再提取 bytecode

## 11. 线程模型

### 11.1 主线程（VM 执行）

`SqueakVM.run()` 是一个无限循环，不断读取并执行字节码。通过 `primitiveYield` 可以让出处理器。

### 11.2 InputNotifyThread

独立线程，定期唤醒主线程处理输入事件。使用 `SqueakVM.class` 对象锁进行同步。

### 11.3 EDT（Event Dispatch Thread）

Swing 的事件分派线程，处理所有 GUI 事件（鼠标、键盘、重绘）。

### 11.4 线程安全问题

- `SqueakVM` 使用 `public static SqueakVM INSTANCE` 全局单例，**不是线程安全的**
- 大量全局静态状态（`image`, `primHandler`, `nilObj`, `trueObj` 等）
- 对象表使用 `WeakReference`，但无并发保护

2. **LargeInteger 原语**：20-39 号原语全部返回失败（`primitive-table.md` 标注 Squeak 2.2 即为 `primitiveFail`，需先确认映像是否依赖）。
3. **声音原语**：170-199 号全部未实现
4. **网络原语**：200-229 号全部未实现
5. **流原语**：65 (next)、66 (nextPut)、67 (atEnd) 未实现

8. **窗口缩放**：需要手动执行两次"restore display"

### 12.2 已知 Bug / FIXME

- `SqueakVM` 中有 `FIXME: safeShift` 注释，bitShift 原语在字节码级别直接 sendSpecial 而非内联计算
- `SqueakObject.install()` 中 Float 转换依赖正确的无符号右移（`>>> 32`），注释中有详细警告
- `BitBlt.pickSourcePixels` 中有 magic number `4294967264`（来自 SqueakJS）
- `ObjectMemory.installObjects()` 中 index 39823 处有调试断点代码
- ~~文件原语中 `fFiles` Map 中的文件永远不会被移除（无 GC）~~ **已修复（2026-10-24）**：关闭文件时移除句柄。
- ~~`primitiveYield` 的等待时间参数被注释为"ignored"~~ **已修复（2026-10-24）**：改为有界等待并可被输入事件唤醒。

### 12.3 架构层面的限制

1. **单线程设计**：整个 VM 基于单线程执行模型，所有状态是全局的
2. **WeakReference GC 依赖**：对象表依赖 Java GC 的弱引用回收，时序不可预测
3. **映像格式硬编码**：仅支持 Squeak 2.2 的 6502 版本格式
4. **测试**：**已过时**。现有 156 个 JUnit 5 测试，覆盖映像加载、对象解析、上下文、显示缓冲、输入同步、位图解压、数值原语、映像保存等。

## 16. 开发建议

### 16.1 如果要添加新的字节码

1. 在 `SqueakVM.java` 中添加新的 `BytecodeExcutor` lambda
2. 在 `initByteCodeTable()` 中注册到对应索引
3. 更新 `bytecode-table.md`

### 16.2 如果要添加新的原语

1. 在 `SqueakPrimitiveHandler.doPrimitive()` 的 switch 中添加 case
2. 实现具体的原语方法
3. 更新 `primitive-table.md`

### 16.3 调试技巧

- 设置 `SqueakConfig.ENABLE_DEBUG_LOGGING = true` 开启详细日志
- 使用 `ObjectUtils.dumpObjOfImage()` 遍历映像中的所有对象
- 在 `SqueakVM.printContext()` 中设置 `byteCount == -1` 的条件断点
- `SqueakPrimitiveHandler` 中的 `primitiveFailed()` 可抛出异常用于定位
